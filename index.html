01 · LLM

It predicts
the next piece.

A large language model writes one small piece of text at a time. At every step it weighs the pieces that could come next, picks one, and then weighs again — now knowing what it just wrote.

Under the hood

Tokens, not words

Models read and write tokens — chunks of text that are often a whole word, sometimes part of one ("un" + "locked"), sometimes punctuation. A typical model has a vocabulary of tens of thousands of tokens.

A probability for every token

At each step the network outputs a score (a logit) for every token in its vocabulary. A softmax turns those scores into probabilities that add up to 1. The stones show the top few; their footprint area is proportional to probability.

Temperature reshapes, then we sample

Before the softmax, each logit is divided by the temperature T: pi = exp(zi/T) / Σ exp(zj/T). Low T sharpens the distribution toward the favourite; high T flattens it. Then one token is sampled from that distribution. Temperature doesn't "pick a surprising word" — it changes the odds.

One token at a time

Generation is autoregressive: the chosen token is appended to the input and the whole prediction runs again. That's why every step brings a fresh set of stones — the odds depend on everything written so far.

Frozen knowledge

Everything the model "knows" was compressed into its weights during training, up to a training cutoff. It can't look anything up on its own — which is the problem the next stop solves. (The words in this scene are pre-written to illustrate the mechanism; no live model is called.)

02 · RAG

It can look
things up.

The river showed the limit: a model only knows what it saw in training. Ask it about something it never read, and it will still answer — confidently.

Retrieval-augmented generation fixes that by handing the model your documents. First it retrieves the few passages closest in meaning to the question, then it generates an answer from them, and can point to its sources.

    Under the hood

    Chunking

    Documents are split into chunks — a few sentences each, like the tablets here — so the model can be given just the relevant pieces rather than whole books.

    Embeddings and similarity

    Each chunk is turned into an embedding: a long list of numbers that places it in a "meaning space". The question is embedded the same way, and a vector search finds the chunks nearest to it (often by cosine similarity). The tablet glow stands in for that score.

    Top-k and the context window

    Only the top-k chunks are kept, because the model's context window is finite and irrelevant text dilutes the answer. Here k = 3: the tray only has three slots.

    Grounding vs. hallucination

    With RAG off, the model still produces fluent text — it just isn't tied to anything true. That's a hallucination. With RAG on, the answer is grounded in retrieved text and can cite it, so a person can check. Retrieval can still miss; good systems measure that too.

    03 · Agent

    It can act.

    Looking things up still means waiting to be asked. An agent is given a goal and works toward it on its own.

    Under the hood it's a loop: the model thinks about what to do next, calls a tool, reads the result, and decides again — until the goal is met. Every step is just text going back and forth.

      Under the hood

      LLM + tools + loop + goal

      An agent is a language model given a goal, a set of tools it may call (search, a calculator, a map), and a loop that keeps running it. Each tool is described to the model by name, purpose and inputs.

      Tool calls are text

      The model doesn't run anything itself. It writes a structured tool call like search("…"); the surrounding program runs the tool and feeds the observation back as more text. Then the model reasons again with that new information.

      Stop conditions

      The loop ends when the model decides the goal is met — or when a guard stops it: a step limit, a budget, or a human check-in. Without them, agents can loop forever.

      Failure modes

      Agents pick the wrong tool, trust a stale source (the old map), or wander. Good agents notice contradictions and correct course; good systems log every step so people can see why it did what it did.

      04 · Skill

      It has
      know-how.

      An agent with tools can act, but not necessarily act well. Knowing which tool exists isn't the same as knowing how to do the job.

      A skill is written know-how: a short instruction file for doing one kind of task well. The agent keeps only the titles in mind, and opens the one chapter a task needs — so it stays focused.

      Under the hood

      Agent Skills

      In Claude's Agent Skills, a skill is a folder with a SKILL.md file: a short header (name, description) and a body of instructions, plus optional scripts or reference files.

      Progressive disclosure

      Only each skill's name and description sit in the model's context up front — a few words each. When a task matches, the agent loads that one skill's full body. That keeps the context small even with many skills installed.

      Skills vs. tools

      A tool is something the agent can do (call a calculator, run a search). A skill is how to do a task well — and often says which tools to use, in what order.

      Skills vs. RAG

      RAG retrieves knowledge automatically, by similarity to the question. A skill is know-how the agent chooses deliberately, by reading the descriptions. Both are just text added to the context — the difference is what it's for and who picks it.
