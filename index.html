01 · LLM

It predicts

A large language model writes text one small piece at a time. At each step it scores every piece that could come next, picks one, and adds it to the text. Then it does the same thing again with the longer text.

Under the hood

Tokens, not words

Models read and write tokens. A token is a chunk of text: often a whole word, sometimes part of a word ("un" + "locked"), sometimes punctuation. A typical model knows tens of thousands of different tokens.

A probability for every token

At each step the model gives every token a score, called a logit. A function called softmax turns those scores into probabilities that add up to 1. The stones show the top few choices, and each stone's area matches its probability.

Temperature changes the odds

Before the softmax, each score is divided by the temperature T: pi = exp(zi/T) / Σ exp(zj/T). A low T makes the favorite even more likely. A high T evens the odds out. Then the model picks one token at random, weighted by those odds. This is called sampling. A high temperature doesn't choose strange words on purpose. It just gives unlikely words a better chance.

One token at a time

This is called autoregressive generation. The chosen token is added to the text, and the model runs again on the whole thing. That's why each step brings a new set of stones: the odds depend on everything written so far.

Frozen knowledge

Everything the model knows was learned during training, up to a date called the training cutoff. On its own, it can't look anything up. The next stop shows how to fix that. (The words in this scene are written by hand to show how this works. No real model is running.)

02 · RAG

It can look
things up.

A model only knows what it saw in training. If you ask about something it never read, it usually answers anyway, and it can sound sure even when it's wrong.

Retrieval-augmented generation (RAG) helps by giving the model your own documents. First it retrieves the few passages that best match the question. Then it generates an answer from those passages and shows which ones it used.

    Under the hood

    Chunking

    Documents are split into short pieces called chunks, a few sentences each, like the scrolls here. That way the model gets only the parts that matter, not whole books.

    Embeddings and similarity

    Each chunk is turned into an embedding: a long list of numbers that captures what it means. Chunks with similar meanings get similar numbers. The question gets an embedding too, and a vector search finds the chunks closest to it, often using cosine similarity. Here, the glow on each scroll shows that closeness score.

    Top-k and the context window

    Only the best few matches are kept, called the top-k. The model can only read so much at once (its context window), and extra text that doesn't help makes answers worse. Here k = 3, so the tray has three slots.

    Grounding vs. hallucination

    With RAG off, the model still writes a smooth answer, but nothing backs it up. A confident answer that isn't true is called a hallucination. With RAG on, the answer is grounded: it comes from real text and lists its sources, so you can check it. Retrieval can still pull the wrong chunks, so good systems test for that too.

    03 · Agent

    It can act.

    So far the model only answers when asked. An agent is given a goal and works toward it on its own.

    It works in a loop. The model decides what to do next, uses a tool, reads the result, and decides again. It keeps going until the goal is done. Each step is written out as plain text, so you can follow along.

      Under the hood

      LLM + tools + loop + goal

      An agent is a language model with three extra things: a goal, a set of tools it can use (here: search, a calculator and a map), and a loop that keeps it running. The model is told each tool's name, what it does and what input it needs.

      Tool calls are text

      The model doesn't run anything itself. It writes a request, called a tool call, like search("…"). The program around it runs the tool and sends the result back as text. Then the model thinks again with the new information.

      Stop conditions

      The loop ends when the model decides the goal is done. Most systems also add limits, like a maximum number of steps, a spending cap, or a person who checks in. Without limits, an agent can keep going forever.

      Failure modes

      Agents can pick the wrong tool, trust out-of-date information (like the old map), or go in circles. A good agent notices when something doesn't add up and changes course. A good system records every step so people can see why the agent did what it did.

      04 · Skill

      It has
      know-how.

      Having tools doesn't mean an agent knows how to use them well for a specific job.

      A skill is a short set of written instructions for one kind of task. The agent only keeps the titles in mind. When a task comes in, it opens the one chapter it needs and follows it.

      Under the hood

      Agent Skills

      In Claude's Agent Skills, a skill is a folder with a SKILL.md file. The file starts with a short header (a name and a description), followed by the instructions. The folder can also hold scripts or reference files.

      Progressive disclosure

      At first, the model only sees each skill's name and description, which is just a few words each. When a task matches one, the agent loads that skill's full instructions. This keeps the model's context small, even with many skills installed.

      Skills vs. tools

      A tool is an action the agent can take, like using a calculator or running a search. A skill explains how to do a task well, and often says which tools to use and in what order.

      Skills vs. RAG

      RAG finds facts automatically, based on how closely they match the question. A skill is a how-to guide, and the agent picks it on purpose after reading the descriptions. Both end up as text the model reads. They differ in what they hold and in how they're chosen.
